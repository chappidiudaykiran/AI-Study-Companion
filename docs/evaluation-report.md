*Audit date: 2026-09-20 · Spec: `Project_Requirements.pdf` (PRD v3.0 Candidate Challenge Edition) · Repo: local checkout `C:\Users\udayk\OneDrive\Desktop\AI Study Companion` (remote `github.com/chappidiudaykiran/AI-Study-Companion`). ## 1. Executive summary (~150 words)

The repository implements the full PRD learning loop end-to-end: Space → Project → PDF upload → async processing → project-scoped RAG Tutor with verified citations and an explicit insufficient-evidence refusal branch → adaptive quiz (MCQ/TF/short/open) with AI-graded open answers → deterministic mastery updates (`0.7·old+0.3·new`) → growth buckets → recommendations, with both a mistake-pattern fast path and a weakest-concept builder, all surfaced through project tabs, a global analytics view, and a functional admin dashboard (users, journey, activity filters, AI usage, evaluation, job retry). Data isolation is enforced server-side on every project/space route plus direct-ID routes, auth uses bcrypt + expiring JWT, and AI calls are abstracted, timeout-guarded, Zod-validated, and logged. Tests (21/21 passing locally) plus curated eval cases and a live rule-based evaluation endpoint exist. The main gaps are operational/documentary: no deployed URL or container/IaC config in the repo, streaming tutor unexercised by the UI, stale doc claims, and no OCR — no broken core loop was found.

## 3. Core learning loop walkthrough (~500 words)

Create Space → Project works through ownership-checked CRUD (`server/src/routes/spaces.js:34,59`, `server/src/routes/projects.js:31,39`, `server/src/middleware/ownership.js:5-18`), with `Project.goal` required (`server/src/models/Project.js:5-9`) so downstream prompts always have a goal to condition on. Upload posts multipart PDF to `POST /api/projects/:id/materials` (`client/src/pages/Project.jsx:287`, `server/src/routes/materials.js:45-76`): multer enforces PDF mimetype/extension and 15 MB, magic bytes are re-checked, then a `Material(queued)` plus an idempotent `Job(doc-process, idempotencyKey=doc-<id>)` are created and the worker is kicked immediately. The UI polls `GET /api/materials/:mid/status` (`client/src/pages/Project.jsx:292`) rendering queued/processing/ready/failed with progress/stage/error — the state machine the PRD requires.

Processing (`server/src/services/pdfService.js:66-165`) extracts text (pdf-parse with pdfjs-dist fallback for bad-xref files), fails cleanly under ~100 chars (the honest scanned-PDF path), extracts 5–8 concepts first via a validated structured call so the Concepts tab populates quickly, then chunks (~800 words/120 overlap, >50 chars), assigns pages by form-feed probe with positional fallback, embeds in batches of 8 with progress 40→92, and marks ready. Retries are safe: chunks are deleted before re-insert, concepts upserted, jobs requeue <3 times with orphan recovery (`server/src/services/jobWorker.js:52-71`).

Ask Tutor posts `{question, session}` (`client/src/pages/Project.jsx:337`) to `POST /api/projects/:id/tutor` (`server/src/routes/tutor.js:47-110`): the user message is persisted, `retrieveEvidence` pulls top-4 project-only chunks (vector, keyword fallback), and the `maxScore<0.18` gate returns the fixed insufficient-evidence message with `grounded:false` before any LLM call. Otherwise the last 6 session messages plus the rebuilt `LearningContext` profile are composed with the evidence into a DATA-only prompt, the structured answer is citation-verified (invented docs remapped to real hits), persisted with `chunkId`-bearing citations, and returned with a retrieval-debug block. Sessions/history/clear endpoints give continuity without resending full history.

Adaptive quiz (`POST .../quiz/start`, `server/src/routes/quiz.js:30-135`) plans up to 12 questions weakest-first with per-question reasons, generates in parallel from per-concept retrieval, and falls back to deterministic prompts on AI failure. Answering (`POST /api/quiz/:qid/answer`, `server/src/routes/quiz.js:138-225`) enforces ownership via the parent project, grades MCQ/TF/short deterministically and open answers via validated AI grading with a length-heuristic fallback, then writes `Attempt` + `updateMastery` + three idempotent events + the mistake-pattern recommendation when warranted, rebuilds learning context, and returns an adaptive next-step (next concept/difficulty/suggestion/flashcard focus). Mastery, growth (`server/src/routes/analytics.js:20-25`), recommendations (`:28-34`), concepts-with-mastery (`:42-97`), adaptive (`:101-106`), and analytics (`:109-118`, `:121-166`) are all live behind `loadProject`, and the single `refreshStats` loader (`client/src/pages/Project.jsx:232-255`) keeps every tab reading the same evidence. Admin (`server/src/routes/admin.js`, `client/src/pages/Admin.jsx`) covers overview, users, journey drill-down, filtered activity, AI usage, evaluation, jobs+retry, and health. Empty/loading/error states are handled per-tab (status pills, progress, refusal badges, fallback text), and data genuinely flows between steps rather than each screen rendering in isolation.

## 4. AI/RAG evaluation (~400 words)

Providers are abstracted in `server/src/services/aiClient.js:1-11`: `AI_PROVIDER=gemini|inception` (default gemini), chat model `mercury-2.5` or `gemini-2.5-flash`, embeddings `text-embedding-004`, 30 s timeout on every call (`:22-28`). When no `GEMINI_API_KEY` exists, `embed()` returns deterministic 64-dim hashed bag-of-words vectors (`:96-105,130-142`) so retrieval still ranks by content — documented in `docs/AI_USAGE.md:13-15`. Gemini embedding dimensionality is provider-opaque (`r.embedding.values`), and `cosine` rejects length mismatches with −1 (`:122-128`), so mixed-dimension corpora degrade to the keyword path rather than silently misranking; there is no pinned-dimension migration story, acceptable for a prototype but worth a note.

The RAG pipeline is extraction → chunking (800w/120 overlap) → batched embedding → project-filtered cosine top-4 (keyword fallback) → context construction (`[i] (doc — Page p)` slices) → citation-verified generation. Grounding is real, not decorative: the evidence gate blocks low-score/empty retrieval before the LLM is called, the prompt constrains answering to the material with an explicit admit-insufficiency rule, and `verifyCitations` (`server/src/routes/tutor.js:28-44`) maps every returned citation to an actual retrieved hit (unknown docs and wrong pages fall back to real chunkIds), with a unit test proving invented docs are rejected (`server/tests/run.js:65-78`). What is *not* proven is citation *page* precision beyond the probe/positional assignment — pages are approximate and unevaluated.

Quiz/assessment generation and grading are all `generateStructured` + Zod with one fix-retry (`server/src/services/aiClient.js:80-94`); schemas live in `server/src/services/aiSchemas.js:10-40`. Failure handling is consistent: quiz-gen falls back to "Explain {concept}…" questions, open-grade falls back to a 60/30 length heuristic with an honest label, tutor failures return 502 with a retry message, and every outcome (including fallbacks and errors) is logged to `AiLog` with retrieval IDs. Prompts throughout mark user/material content as DATA-never-instructions, which is the injection mitigation — reasonable but prompt-level only. Evaluation combines 10 curated cases (`eval/cases.js`) with a live rule-based endpoint (`server/src/services/evalService.js:7-56`: citation rate, refusal count, per-feature errors/latency) surfaced in Admin; there is no model-graded judge or stored regression history, so prompt/model changes rely on re-running unit tests + eyeballing live metrics, exactly as the README regression rule states.

## 5. Mastery/recommendation evaluation (~250 words)

Mastery is deterministic and evidence-derived — no hardcoded or random values were found (no `Math.random` in the loop). `updateMastery` (`server/src/services/masteryService.js:5-23`) seeds first attempts directly (so the 2nd-failure rule fires on time) then applies `round(0.7·old+0.3·new)` with a 30-entry history cap and a mistakes counter incremented on scores <60. Flashcards nudge ±4 (`:81-101`). Growth buckets (`server/src/services/recommendService.js:45-53`) compare the last two history points with ±5 thresholds. The adaptive picker (`server/src/services/masteryService.js:50-77`) weights low mastery, mistake counts, and per-concept recent failures — genuinely beyond naive wrong→easy, with difficulty (`:26-31`) and human-readable reasons (`:33-47`) attached to every pick.

**Known open item — recommendation chain zero rows: FIXED with evidence.** Two independent creation paths now exist: (a) the mistake-pattern fast path in `server/src/routes/quiz.js:182-196` creates a `mistake-pattern:<concept>` recommendation (plus `recommendation.created` event) on the second sub-60 attempt — the first-attempt-seeds-mistakes=1 fix (`server/src/services/masteryService.js:8-13`, tested in `server/tests/run.js:59-64`) is precisely what makes the `mistakes>=2` gate reachable; (b) the weakest-concept builder `buildRecommendation` (`server/src/services/recommendService.js:11-43`) is invoked on every `GET .../recommendations` and `GET .../adaptive`, always returning at minimum the `no-data` row for empty mastery and otherwise creating/deduping a weak-concept row. A zero-row outcome is therefore no longer reachable through these endpoints. I could not mint a live row during this audit (no running DB), so the "real row" confirmation remains an environment limitation, not a code gap.

**Recommendations page "not found": resolved as routing misunderstanding, not data bug.** There is no `/recommendations` route by design (`client/src/App.jsx:512-521`); recommendations is a `?tab=` view inside `Project` (`client/src/pages/Project.jsx:24-48,1781-1846`) fed by `GET .../recommendations` + `GET .../adaptive` (`:242-252`). An empty state previously looked like a missing page; with the chain above it now renders content. ### Data isolation (dedicated subsection)

Isolation is enforced server-side, not client-side. `loadSpace`/`loadProject` (`server/src/middleware/ownership.js:5-18`) scope every `:spaceId`/`:projectId` route to `req.user._id`, returning 404 (no existence leak). Direct-ID routes re-check ownership independently: materials status/delete (`server/src/routes/materials.js:81,112`), quiz answer via parent project (`server/src/routes/quiz.js:144-145`), flashcard routes via parent project, and every tutor/analytics path carries `loadProject`. Retrieval itself filters `Chunk.find({project})` (`server/src/services/retrievalService.js:6`), and the U2 cross-project case is an explicit eval case (`eval/cases.js:9`). Admin routes are `auth+requireAdmin` (`server/src/routes/admin.js:17`). No IDOR bypass was found by reading the routes; the caveat is that isolation is verified by code inspection plus a rule-assertion test (`server/tests/run.js:38-41`), not a live two-user IDOR probe (no running DB in this environment).

Remaining security posture: bcrypt cost 10 with min-length + change/reset checks (`server/src/routes/auth.js`); JWT expiry configurable (default 7d) but no refresh/rotation; rate limits on auth/AI/upload; Zod validation at AI and API boundaries with a 1 MB JSON cap; PDF handling via mime+extension+magic bytes with cascade delete; prompt-level data/instruction separation but no injection test suite; `server/.env` present locally with keys (types only ever reported) and correctly git-ignored and untracked. No committed secrets, no hardcoded API keys, no SQL (Mongoose, no raw queries), no path traversal (multer dest + IDs, no user-controlled paths).

## 7. Document processing evaluation (~200 words)
