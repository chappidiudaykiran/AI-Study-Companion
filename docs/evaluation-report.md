# Evaluation Report — AI Study Companion vs PRD v3.0

*Audit date: 2026-09-19. Spec: `Project_Requirements.pdf` (PRD v3.0). Method: full repo read + `npm test` run + static trace. No source edited.*

## 1. Executive summary (~150 words)

The core learning loop is implemented end-to-end and connected: Space → Project → PDF upload → async processing → grounded Tutor with citations → unsupported refusal → adaptive MCQ/open quiz with AI grading → EMA mastery → growth → recommendations → project/global analytics → admin. Data isolation is consistently enforced (`loadProject`/`user`-scoped queries) and structured AI outputs are Zod-validated with retry. The previously reported zero-recommendations chain now produces rows (`server/src/routes/quiz.js:174-196`, `server/src/services/recommendService.js:11-43`), with one off-by-one delay remaining. The "Recommendations not found" issue was a missing-page expectation, not a routing bug: recommendations are a banner + `GET recommendations` endpoint, and that endpoint now always returns a row. Main gaps are prototype-grade: no streaming, page numbers approximated, tests are pure-function only, no deployed URL is recorded in the repo, and prompt-injection defense is instruction-level. No CRITICAL blockers; overall code score 87.8%.

## 3. Core learning loop walkthrough (~500 words)

Create Space → Project works end-to-end: `POST /api/spaces` (`spaces.js:25`) and `POST /api/projects` with `Space.findOne({_id, user})` ownership (`projects.js:20-25`) persist `user`-stamped rows; the sidebar creates both inline with validation (`App.jsx:94-125`) and the Home page answers "where was I" from `GET /analytics/global` (`analytics.js:121-166`). Upload → Process: `POST /projects/:id/materials` (`materials.js:29-54`) stores a random-path file, creates `Material(queued)` + `Job(doc-process, idempotencyKey=doc-<id>)`, and kicks `runOnce()` immediately rather than waiting for the 10 s cron poll (`jobWorker.js:70`). Progress/stage surface via `GET /materials/:id/status` (`materials.js:58-74`), and the frontend polls it. Processing (`pdfService.js:18-122`) extracts text with `pdf-parse`, fails fast on <100 chars (scanned PDFs explicitly out of scope), extracts ≤8 concepts from the first 6000 chars, chunks 800 words/120 overlap, embeds in batches of 8, and marks `ready`; embed/concept failures degrade rather than fail the job. Ask Tutor: `POST /projects/:id/tutor` (`tutor.js:25-91`) persists the user message, retrieves top-4 project-scoped chunks (vector with keyword fallback), gates on `maxScore<0.18` to a refusal, injects goal + weakest/strongest + recent accuracy + last-6 session messages, and returns `{answer, citations, confidence, grounded, retrieval}`; the Project page renders citation pills plus a Sources panel (`Project.jsx:1036-1038,1179-1197`). Quiz: `POST .../quiz/start` (`quiz.js:30-135`) picks weakest-first concepts with per-question reasons, retrieves 2 evidence hits per concept, and generates questions in parallel (perf fix over sequential); answers (`quiz.js:138-225`) grade MCQ/TF/short deterministically and open answers via `gradeSchema` AI grading with explanatory `covered/missing/feedback`, then synchronously create Attempt + Mastery + 3 events + LearningContext refresh and possibly a mistake-pattern Recommendation. Mastery/Growth/Recommendations/Analytics all read live rows (`quiz.js:228-233`, `analytics.js:20-118`); the adaptive banner (`recommendService.js:58-138`) drives every tab from one weakest-evidence payload. Admin (`admin.js:16-133`, `Admin.jsx`) covers overview/users/spaces/projects/activity/AI logs/jobs/evaluation/journey. Steps genuinely pass data (retrieval hits → prompt → citations; quiz evidence → questions; attempts → mastery → recommendations), not just co-rendered screens. Weakest links: page numbers are positional estimates, first mistake is under-counted, and long evidence chains stay synchronous.

## 4. AI/RAG evaluation (~400 words)

Provider abstraction is real: `AI_PROVIDER=gemini|inception` swaps chat between `gemini-2.5-flash` and `mercury-2.5` without caller changes (`aiClient.js:6-10`, `inceptionClient.js:18-35`, 30 s timeout both paths), and `docs/AI_USAGE.md:8-20` accurately describes this setup (chat models, `text-embedding-004`, cosine top-k + keyword fallback, Zod validation, AiLog). One doc-code nuance: embeddings always go through Gemini (`aiClient.js:96-105`) even when chat uses Inception, so an Inception-only deploy still needs `GEMINI_API_KEY` — the doc doesn't call this out. No embedding dimension constant exists; `Chunk.embedding` is `[Number]` (`Chunk.js:9`) with length-mismatch guard returning -1 (`aiClient.js:115-121`), so dimension drift fails closed into the keyword path. The pipeline is extraction → 800/120 word chunking → batched embed → project-scoped retrieval → prompt construction → citation return. Retrieval (`retrievalService.js:5-49`) loads ≤500 project chunks, embeds the question, cosine-ranks, and falls back to word-overlap scoring when embedding fails; `topK=4`, `score>0` filter, material filenames attached. Grounding is genuine: project filter at query time, hard refusal gate, DATA-only prompt framing, persisted `citations[]` on assistant messages plus `retrievalIds` on AiLog, and refusal events counted in evaluation (`evalService.js:15-17`). Gaps: the 0.18 gate is permissive, keyword fallback can ground weakly-related chunks, nothing verifies the LLM-returned doc/page against actual hits, every citation copies `hits[0].chunkId` (`tutor.js:84`), and page numbers are round-robin estimates (`pdfService.js:76-84`), not PDF-text mappings. Quiz generation grounds each question in 2 retrieved hits with a deterministic fallback question on AI failure (`quiz.js:115-120`); grading is exact-match for MCQ/TF/short and `gradeSchema`-validated AI grading for open answers with a length heuristic fallback (`quiz.js:168-171`). Structured outputs are enforced (`aiClient.js:80-94`: strip fences, `JSON.parse` + `schema.parse`, one fix-retry then throw → 502), and every AI call logs model/latency/tokens/cost/status (`aiClient.js:35-43`). AI failures degrade (keyword search, fallback question, heuristic grade, 502 with retry) rather than corrupting state.

## 5. Mastery/recommendation evaluation (~250 words)

The chain is synchronous and field-correct: `Attempt.create` (`quiz.js:174`), `updateMastery` (`quiz.js:175` → `masteryService.js:4-17`), three `logEvent` writes (`quiz.js:176-178`), `updateAfterAttempt` → `LearningContext` upsert (`contextService.js:44-58`), and conditional `Recommendation.create` (`quiz.js:186-191`). Prior "zero rows" is fixed in the sense that every answered question now writes Attempt + Mastery + events; recommendations additionally self-create on `GET .../recommendations` via `buildRecommendation` (`analytics.js:28-34`), so the page can never be empty — this resolves the old "not found" report, whose root cause was empty-recommendations (no fallback row), not a missing frontend route (recommendations were always a banner, and `App.jsx:411-421` correctly has no `/recommendations` route). Remaining defect, off-by-one: `Mastery.create` omits `mistakes` (`masteryService.js:7`), so a first-attempt failure stores `mistakes=0` and the `mistakes>=2` gate (`quiz.js:182`) only fires on the third failure, contradicting the "2nd+ mistake" comment (`quiz.js:180`). `buildRecommendation` dedups by design (`recommendService.js:14-17,39`): no new Attempt since last rec, or identical fallback text, returns the old row — correct anti-spam behavior that reads as "stale" on repeated same-weakness quizzes. Growth is a pure map over mastery history (`recommendService.js:45-53`), never a stored row, so "zero growth rows" is expected; first-quiz delta is 0/stable. Values are derived (EMA 0.7/0.3, difficulty bands, priority formula), not random, though `pickNextConcept`'s recency term is global rather than per-concept (`masteryService.js:53-54`), weakening adaptivity. No live Step-3 row could be created here (no DB in this environment); verification is by code-path trace, and a fresh DB run is recommended as the final check.

## 6. Data model & security findings (~350 words)

Seventeen models cover the spec graph with `user`+`project` ownership threads and sensible uniqueness (`Mastery {project,user,concept}`, `LearningContext {project,user}`, `Job.idempotencyKey`, `Event.key` sparse, `Concept {project,name}`). `Question`/`Flashcard`/`Chunk` omit `user` by design and rely on the parent-project gate — sound under single-owner projects.

### Data isolation (dedicated subsection)

Every project/space endpoint was traced: spaces (`spaces.js:15-59`), projects (`projects.js:20-39`), materials (`materials.js:29-97`), tutor (`tutor.js:25-137`), quiz (`quiz.js:30-233`), flashcards (`flashcards.js:20-155`), analytics (`analytics.js:20-166`) all pass through `loadSpace`/`loadProject` (`ownership.js:5-18`, `findOne({_id, user})` with 404 masking) or explicit `{..., user}` filters plus `Project.findOne({_id: q.project, user})` on ID-based quiz answers (`quiz.js:141-145`). Retrieval is project-filtered at query time (`retrievalService.js:6`). Admin is `auth+requireAdmin` gated (`admin.js:14`) with password hashes excluded (`admin.js:30,107`). No IDOR found: cross-user reads return 404 rather than leaking. Verdict: PASS with HIGH confidence on static trace (no live two-user test possible here).

Auth uses bcrypt-10 + JWT 7 d expiry (`auth.js:19-32,42-51`), Zod validation on register/profile/password flows, generic forgot-password replies, sha256-hashed single-use reset tokens with 1 h expiry, and dev-link exposure only outside production (`auth.js:102-143`). Rate limits cover auth/AI/upload (`rateLimit.js:14-32`). Uploads use random multer paths, original names stored as metadata only, no user-controlled `fs` joins, so no path traversal (`materials.js:19-36`, `pdfService.js:37`); cascade delete is ownership-checked (`materials.js:89-97`). Weaknesses: PDF type check is mimetype-only (spoofable; low risk since files are only parsed, never executed/served); prompt-injection defense is DATA-framing instructions in prompts, with no output containment or tool sandbox (no tool-calling exists, which bounds the blast radius); `Event` dedup is key-scoped but error-swallowing (`eventService.js:10-15`); no secret values are committed — only `.env.example` placeholders are tracked (`.gitignore:7-8` verified via `git ls-files`). No exposed-secret finding.

## 7. Document processing evaluation (~200 words)

Upload → `queued` → 10 s-cron plus immediate `runOnce()` kick → `processing` → concept extraction → chunk/embed/index → `ready`, with progress/stage updates (`Reading PDF` → `Extracting concepts` → `Splitting` → `Indexing (n/m)` → `Ready`) visible via the status endpoint. Retry is 3-attempt requeue with 500-char error truncation, orphan recovery for `processing` jobs older than 2 min at worker start, and manual admin retry (`jobWorker.js:9-76`, `admin.js:67-76`); idempotency comes from `doc-<materialId>` unique keys plus skip-if-ready and `deleteMany`-before-insert on retry (`materials.js:45`, `pdfService.js:22-23,78-79`). Corrupt PDFs fail via `pdf-parse` throw; empty/scanned files get an explicit "needs OCR — out of prototype scope" failure (`pdfService.js:40`); oversized files are rejected at 15 MB by multer. Gaps: `MAX_PDF_MB` env is ignored (hardcoded limit), no magic-byte check, no content-hash dedup (re-upload = full re-cost), `uploads/` is ephemeral on Render (restart loses files while DB rows remain → orphaned `filePath`), single-process single-job polling won't scale, and admin retry doesn't reset the retry counter. Within prototype scope the pipeline is correct and observable; for production, move files to object storage and persist retry counts properly.
